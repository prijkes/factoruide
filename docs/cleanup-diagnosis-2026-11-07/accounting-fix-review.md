# Independent accounting-fix review

Decision: **Approve** the current accounting patch for the narrowly defined abandoned-work defect. No Critical, Important or Minor findings in the reviewed production changes or the 14 accounting oracles.

Reviewed the current diff in `state.rs`, `sim.rs`, `step.rs` and `evaluate.rs`, the complete `tests/abandoned_work.rs`, and the surrounding execution/settlement paths. This includes the strengthened alternative/stock test with 96 seconds of separately rewarded legacy work beside 88 seconds of unpaid actual work. I made no production/test edits and ran no builds, tests or planners. The coordinator reports 14/14 focused tests passing; that execution result is supplied evidence, not an independent rerun by this reviewer. The coordinator's broader verification remains separate.

## Findings by invariant

- **Execution provenance:** `objective_work` records `kill_work + other` only in the non-shared branch. Those local values were calculated from the selected executing objective, remaining imported progress, current combat cost and actual stock consumption before the XP update. The record therefore matches the actual gross addition to fighting. Recording does not occur in `hold`, initial-state import or mere shared/dungeon completion. Removing the old nominal-objective loop avoids duplicate classification and exclusion errors for imported complete or partial work.
- **Imported progress and real alternatives:** The imported-complete test exercises both start omission and retained-quest expiry with unrelated rewarded legacy fighting, so a zero cap cannot hide false prior work. The partial-progress tests cover active, expired and genuinely rewarded outcomes. The alternative/stock test's productive 96-second component makes its 88-second assertion discriminate actual selected cost from an inflated canonical estimate; the cap cannot make both implementations pass.
- **Direct beneficiary settlement:** Abandoning one beneficiary leaves surviving beneficiaries and all their pending seconds intact. Removing the final beneficiary transfers its seconds once to `orphaned_work` before deleting the entry. Existing canonical sorting and merging remain in place. Reward settlement still removes every chunk justified by that real reward and adds it to direct reward protection, without orphaning it. An already settled entry cannot be found and transferred again.
- **Legacy settlement:** The sorted ledger aggregates one row per quest. Abandonment removes and transfers that row; successful turn-in removes it without creating orphan liability. Repeated settlement is a no-op. Both paths are wired beside direct settlement, and the existing completion-error return precedes reward settlement. Legacy reward seconds never enter `rewarded_kill_work`.
- **Gathering and reward protection:** Physical `together` behavior is unchanged. Final accounting retains the existing `spent.fighting - rewarded_kill_work` cap. The tests cover gathering before and after kills, an expired gathering owner with a genuine shared reward, and rewarded gathering that must not shield unrewarded direct kills. This preserves the intended direct-reward protection rather than treating discounted gathering as protected killing.
- **Memory and snapshots:** `Rc<Vec<(u32, f64)>>` uses copy-on-write on actual mutation, and both settlements remove the corresponding row. Multiple objectives accumulate in one active-quest row. The new scalar retains no IDs or event history. The bounded-ledger test checks aggregation, snapshot immutability, removal on both settlement paths, and idempotence. No cache caps or existing direct-ledger bounds change.
- **Incremental reuse:** Both new fields are initialized explicitly. Exact suffix comparison includes ledger equality and scalar bit equality in addition to the prior direct fields. The ownership regression gives equal physical progress and time but different ownership, exercising pending rows and post-expiry orphan liability separately. It checks the expected 288-second score difference against full ordinary simulation, so this is stronger than comparing two accidentally equal routes.
- **Scope:** The four production files implement the previously reviewed small design. No route search, data, defaults, UI, physical combat-time, XP, travel, reward, timer or dungeon behavior is changed by these edits. Actual legacy cost replaces nominal cost only for final work classification.

## Boundaries of approval

The retained global gathering cap is still an approximation for arbitrary mixtures of productive and unproductive legacy work. This patch does not redesign attribution of each saved gathering second; that pre-existing limitation is explicitly documented in `fix-design-review.md` and is not a new regression or a blocker for the defined conservation fix.

The coordinator reports that chain and baseline old-semantics archived captures matched all checked observables before production accounting edits, and that the main cleanup regression was independently traced to the training anchor. This accounting approval does not independently re-audit those artifacts or attribute the roughly 31-percent cleanup loss to abandoned-work accounting. The accounting defect and its finite real-route oracles stand independently.

Approval applies to the inspected production diff and current 14-test source. Broad test/Clippy results and any subsequent source changes must be assessed by the coordinator before committing.
