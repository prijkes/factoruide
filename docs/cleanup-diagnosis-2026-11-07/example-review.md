# Independent review of the archived-run diagnostic example

Verdict: **APPROVE** for the specified archived chain diagnostic. No Critical, Important, or Minor defects identified in the reviewed example. This approves the instrumentation and comparison method; it does not assert that the replay has passed or that the cleanup root cause is already established.

Scope: read-only inspection of `crates/fg-route/examples/cleanup_diagnose.rs`, its helper tests, the implementation plan and worker report, the original comparison harness, relevant preparation/search/acceptance/scoring/finalization source, and selected metadata from the held-out 028 Forever Gnome Mage 20–40 seed 20261107 chain artifact. No builds, tests, planners, source changes, or artifact modifications were performed by this reviewer. The coordinator owns executable verification and source/data provenance.

## Findings checked

- The example deserializes the archived `effective_request` and passes it directly through the same ordinary preparation and greedy construction path. It does not reapply variant defaults or replace the archived parameters. It separately compares the round-tripped request and prepared effective parameters against the archive, so preparation drift cannot silently pass the observable-equality classification.
- Both timed stopping conditions in `quality_compare.rs` are removed: `Effort::Time(remaining)` becomes `Effort::Tries(tries)` and the cutoff callback becomes unconditional continuation. Attempt count is parsed from exactly one completed cleanup log and checked against the reproduced log. The inspected archive records 59,526 tries and 367 improvements, with 367 search callbacks including the initial callback; these are deliberately separate gates.
- Both parameter records must have matching seed and edition, zero annealing and LAHC, deterministic greedy construction, and solo group size. Empty mates and the single-start harness identity are required. The example never attaches a sharing member. Archived `share_every=500` is consequently inert, matching the original harness. With annealing and LAHC zero, the differing progress calculation cannot change the acceptance draw or decision.
- Callback comparisons cover the initial callback and the entire ordered search sequence, checking exact score, player seconds, stop count, and search stage. The original harness records no additional non-timestamp search callback fields. Final checks separately cover exact score/player time, typed stop order, and full stop identity records including quest IDs. Newly measured values cross the archive's JSON serialization/parsing boundary before comparison; there is no epsilon comparison. These are comparisons of recorded observables, not unavailable archived intermediate route snapshots.
- Count parsing requires unsigned counts with improvements no greater than attempts and rejects missing, duplicate, or incomplete completion records. Typed stop decoding rejects unknown kinds, overflowing indices, and overflowing objective ordinals. Archived stops are only compared with generated stops and are not used as executable route input or unchecked model indices.
- The cleanup callback only copies stage labels and stop vectors. All snapshot scoring and tracing occurs after normal cleanup and `job::finalize_route` have finished. Each stage receives its own ordinary `Planner::new`, with no `replaying()` mode and no reuse of the search planner's memo tables. The final snapshot is scored in the same fresh manner.
- Stage output includes complete stops, full trace, explicit breakdown fields otherwise skipped by serialization, quest identity, listed and actually entered dungeons, actual turn-ins and abandonments, and removed-quest dungeon requirements. Consecutive stage deltas are calculated from the replayed values. The weighted decomposition matches `Sim::weights` and the explicit end-goal terms in `step.rs`. Unmet reputation-goal count penalties and floating-point summation order remain honestly labeled in the residual, rather than being attributed to an unrelated component.
- Existing output paths are refused up front; the final file open also uses `create_new`, protecting against an intervening file creation. The archive is read-only and the game database is opened read-only. The example does not alter app state.
- A failed equality gate produces `diagnostic_reproduction`; even all gates passing yields only `recorded_observables_match_pending_provenance`, with an explicit source/lockfile/data/override requirement and no timing claim. This accurately limits what the code itself establishes.

## Interpretation requirements retained

Before attributing the original archived loss to a particular cleanup pass, inspect the resulting gates and compare the freshly replayed `SelectedInput` score/player time with the last raw search callback. Any discrepancy there is an evaluation/replay issue preceding the cleanup deltas and must not be assigned to the first transform. Check the residual size, actual removed quest identities and trace consequences when interpreting the largest stage delta. Confirm source, lockfile, data, and override provenance separately before using the phrase exact archived replay. These are evidence-interpretation requirements already within the plan, not requests to expand the implementation.
